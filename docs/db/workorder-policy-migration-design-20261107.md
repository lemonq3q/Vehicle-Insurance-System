# 工单数据库合并说明

按 2026-11-07 最后确认的结构，以本文件替代此前新增独立保单表的方案。

## 最终结构

| 表 | 保存内容 |
| --- | --- |
| `biz_workorder` | 原工单资料 + 三种起期 + 三类保单的公司、号码、终期 + 核保承保反馈 + 支付收款资料 |
| `biz_workorder_quote` | 三种保费、车船税、上下游政策费用，以及原报价备注/流程记录 |

两表仍以 quote 的企业和 workorder_id 关联主表企业和 ID。投保险种、文件、物流等表不调整。

不新增合计保费和保单应付金额列；`required_pay_amount` 作为旧支付环节的录入值保留，不用计算结果覆盖。

## 字段迁移

| 来源 | 目标 |
| --- | --- |
| 主表现有商业、交强起期 | 原字段原值保留 |
| 原本没有的非车险起期 | 主表新增 `non_motor_insurance_start_time`，暂为 NULL |
| underwriting 的两种保单号、核保/承保备注、失败原因、核保/完成时间 | 原名迁入主表 |
| payment 的金额、姓名、联系方式、证件号、开户行、卡号及支付反馈 | 原名迁入主表 |
| 原本没有的三类保险公司、三类终期、非车险保单号 | 主表新增对应字段，暂为 NULL |
| quote 的保费、车船税、非车险名称/保额、报价反馈和时间 | 原地保留 |
| commission 的计算方式、四类比例、四类政策金额 | 按上下游展开为 quote 的 `upstream_*` / `downstream_*` 字段 |

新公司字段为 `commercial_insurer_name`、`compulsory_insurer_name`、`non_motor_insurer_name`；新终期字段为三类 `*_insurance_end_time`，时间均为 Unix 秒；新增 `non_motor_policy_no`。

commission 的 `vehicle_tax_*` 映射到 quote 的 `upstream_vehicle_and_vessel_tax_*` / `downstream_vehicle_and_vessel_tax_*`，对齐当前业务字段命名。

原子表 ID、创建/更新时间等审计信息完整保留在原表备份中，不覆盖工单主表自己的审计字段。原表没有的资料不推测补齐。

## 增量文件

`backend/db/migration/V20261107_01_merge_workorder_business_tables.sql`

- 在线表和对应归档表一起迁移。先复制主表和 quote 到影子表，再合并并逐字段校验，最后原子切换。
- 已适配 `Result_5.csv` 中十个审计时间触发器：原触发器随旧表备份保留；数据校验后为新主表、quote 安装四个触发器，保持插入补齐空时间、更新刷新 `updated_at` 的规则。归档表不新增触发器，文件/险种/物流表不变。没有旧触发器的在线主表、quote 也统一启用这套时间维护规则。
- 触发器先在影子表上创建并检查，全部成功后才换表，历史审计时间不会被迁移过程刷新。未知触发器及外键仍阻止迁移；失败时不得跳过检查直接换表。
- 十张原表全部改名为 `原表名_bak261107` 保留，不删除旧数据；underwriting、payment、commission 原业务表名退出使用。
- 只有 commission 没有 quote 的工单，会补建 quote 行。存在重复、孤儿、企业归属/删除状态不一致、未知字段或上下游方向时中止，避免猜测迁移。
- 执行前完整备份、暂停所有业务与定时任务写入。脚本不设置维护确认开关；使用 MySQL 8.0 客户端执行，不使用忽略错误选项。
- 需要额外磁盘空间容纳四张影子表；源数据复制和校验期间必须一直停写。执行成功后，部署适配新结构的后端再恢复服务，旧后端不能直接运行。
- 失败可能保留影子表及迁移过程定义；成功或失败均不自动清理数据。重跑发现影子表/备份会中止，须核对上次状态。
