# 企业 SaaS 近期提醒种类与规则

## 1. 文档说明

本文档依据当前 SaaS 后端实际实现整理，描述企业门户近期提醒及客服监控提醒的类型、触发条件、阈值、严重程度、文案和合并规则。

提醒生成任务编号为 `saas-recent-reminders`，由分布式维护流程执行。任务在余额访问状态校准后、订阅到期处理前运行，并要求 SaaS 后端和监控后端均处于可用状态。

## 2. 当前默认阈值

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `REMINDER_FIRST_EXPIRY_WARNING_DAYS` | 7 天 | 套餐到期或自动续费的首次提醒阈值 |
| `REMINDER_URGENT_EXPIRY_WARNING_DAYS` | 1 天 | 套餐到期或自动续费的紧急提醒阈值 |
| `REMINDER_QUOTA_FIRST_PERCENT` | 80% | 工单额度首次预警阈值 |
| `REMINDER_QUOTA_URGENT_PERCENT` | 90% | 工单额度紧急预警阈值 |
| `REMINDER_NEAR_SUSPENSION_RATIO` | 80% | 欠费接近停服的预警比例 |
| `REMINDER_DATA_DELETION_WARNING_DAYS` | 30、15、3 天 | 企业资料清理倒计时提醒阶段 |
| `BALANCE_SUSPEND_THRESHOLD` | -100.00 元 | 套餐因欠费暂停的余额阈值；余额严格低于此值时停服 |
| `BALANCE_RESTORE_THRESHOLD` | 0.00 元 | 欠费暂停后恢复服务所需余额阈值；余额需高于此值 |
| `WORKORDER_OVERAGE_UNIT_PRICE` | 0.20 元/单 | 超额工单预计费用单价 |
| `ENTERPRISE_DATA_RETENTION_DAYS` | 90 天 | 套餐结束后企业车险资料保留期限 |

以上参数均可通过部署环境变量调整；本文其余示例按默认值说明。

## 3. 提醒种类及触发规则

当前共实现 8 类提醒。

### 3.1 自动续费余额不足

- 类型编码：`AUTO_RENEW_BALANCE_INSUFFICIENT`
- 严重程度：`WARNING`（重要）
- 适用条件：订阅状态正常、已开启自动续费，并进入下次续费时间前 7 天或 1 天的提醒窗口。
- 余额判断：`可用余额 = 钱包余额 - 冻结金额`；仅当可用余额小于预计续费金额时触发。
- 阶段：剩余不超过 7 天为 `7D`，阶段等级 10；剩余不超过 1 天升级为 `1D`，阶段等级 20。
- 标题：`自动续费余额不足，请及时充值`
- 内容模板：`您的“{套餐名称}”套餐将于 {续费时间} 自动续费，预计续费金额为 ¥{续费金额}。当前可用余额为 ¥{可用余额}，尚缺 ¥{差额}，请于续费前完成充值。`
- 失效时间：下次续费时间；若下次续费时间为空，则使用套餐结束时间。

### 3.2 未开启自动续费的套餐即将到期

- 类型编码：`SUBSCRIPTION_EXPIRING_NO_AUTO_RENEW`
- 严重程度：`WARNING`（重要）
- 适用条件：订阅状态正常、未开启自动续费，并进入套餐结束前 7 天或 1 天的提醒窗口。
- 阶段：剩余不超过 7 天为 `7D`，阶段等级 10；剩余不超过 1 天升级为 `1D`，阶段等级 20。
- 标题模板：`套餐将在{剩余天数}天后到期`
- 内容模板：`您的“{套餐名称}”套餐将于 {到期时间} 到期，剩余 {剩余天数} 天。当前未开启自动续费，请及时续费或开启自动续费。`
- 失效时间：套餐结束时间。

到期天数采用向上取整。例如距离到期还有 6 天 1 小时，按剩余 7 天处理；到期后不再生成此提醒。

### 3.3 工单额度即将用尽

- 类型编码：`WORKORDER_QUOTA_NEAR_LIMIT`
- 严重程度：`WARNING`（重要）
- 适用条件：订阅状态正常、套餐工单额度大于 0，且当前周期使用量尚未达到套餐额度。
- 使用率计算：`向下取整(已使用工单数 × 100 ÷ 套餐额度)`。
- 阶段：使用率达到 80% 为 `80_PERCENT`，阶段等级 10；达到 90% 为 `90_PERCENT`，阶段等级 20。
- 标题：`工单额度即将用尽`
- 内容模板：`本周期套餐额度为 {额度} 单，已使用 {使用量} 单（{使用率}%），剩余 {剩余额度} 单，请提前评估用量。`
- 失效时间：当前套餐周期结束时间。

使用量只统计当前订阅周期内、属于本企业且未被逻辑删除的工单。

### 3.4 工单数量达到或超过套餐额度

- 类型编码：`WORKORDER_QUOTA_REACHED`
- 严重程度：`WARNING`（重要）
- 适用条件：订阅状态正常，且当前周期工单使用量大于或等于套餐额度。
- 提醒节点：按照 1、2、4、8、16……倍的指数阶段升级，不按固定数量线性重复提醒。
- 阶段编码：`MULTIPLIER_1`、`MULTIPLIER_2`、`MULTIPLIER_4`、`MULTIPLIER_8`……
- 阶段等级：1 倍为 10、2 倍为 20、4 倍为 30、8 倍为 40，以此类推。
- 标题模板：`工单数量已达到套餐额度的{倍数}倍`
- 内容模板：`本周期套餐额度为 {额度} 单，现已使用 {使用量} 单，达到额度的 {倍数} 倍，超出 {超出数量} 单，当前预计超额费用为 ¥{预计费用}。`
- 预计费用：`最大值(0, 使用量 - 套餐额度) × 超额工单单价`。
- 失效时间：当前套餐周期结束时间。

例如额度为 1000 单时，在使用量达到 1000、2000、4000、8000 单时依次升级提醒；处于两个节点之间时维持上一个阶段，不新增提醒。

### 3.5 钱包余额变为负数

- 类型编码：`WALLET_BALANCE_NEGATIVE`
- 严重程度：`WARNING`（重要）
- 触发条件：企业钱包余额小于 0。
- 阶段：`NEGATIVE`，阶段等级 10。
- 标题：`账户余额已为负数，请尽快充值`
- 内容模板：`当前账户余额为 ¥{余额}，请尽快充值，以免欠费继续增加并影响套餐使用。`
- 合并周期：以钱包本次从非负数跨越到负数时产生的交易 ID 标识一次欠费周期；没有该交易时使用当前负余额周期标识。
- 失效时间：当前套餐结束时间。

### 3.6 钱包余额接近套餐停止阈值

- 类型编码：`WALLET_BALANCE_NEAR_SUSPENSION`
- 严重程度：`CRITICAL`（紧急）
- 默认预警值：`-100.00 × 80% = -80.00 元`。
- 触发区间：余额小于等于 -80.00 元且大于等于 -100.00 元。
- 阶段：`NEAR_SUSPENSION`，阶段等级 10。
- 标题：`账户余额接近套餐停止阈值`
- 内容模板：`当前余额为 ¥{余额}，已达到欠费预警阈值 ¥{预警值}。余额低于 ¥{停服阈值} 时套餐服务将暂停，请尽快充值。`
- 合并周期：与负余额提醒使用相同的欠费周期标识，但属于独立提醒类型。
- 失效时间：当前套餐结束时间。

### 3.7 套餐已因欠费暂停

- 类型编码：`SUBSCRIPTION_SUSPENDED_ARREARS`
- 严重程度：`CRITICAL`（紧急）
- 触发条件：钱包余额为负数，订阅状态为暂停，并且暂停原因为 `ARREARS`。
- 阶段：`SUSPENDED`，阶段等级 10。
- 标题：`套餐服务已因欠费暂停`
- 内容模板：`当前余额为 ¥{余额}，已低于暂停阈值 ¥{停服阈值}，套餐已暂停。请充值至高于 ¥{恢复阈值} 以恢复服务。`
- 提醒标识包含实际暂停时间，用于区分不同的停服事件。
- 失效时间：当前套餐结束时间。

默认配置下，余额严格低于 -100.00 元时暂停服务；恢复时余额必须高于 0.00 元，中间区间作为缓冲，避免服务状态反复切换。

### 3.8 企业资料即将进入清理流程

- 类型编码：`ENTERPRISE_DATA_DELETION_APPROACHING`
- 严重程度：`CRITICAL`（紧急）
- 适用条件：套餐已经结束，但尚未到达资料清理日。
- 清理日计算：`套餐结束时间 + 资料保留天数`，默认保留 90 天。
- 阶段：剩余不超过 30 天为 `30D`、等级 10；不超过 15 天升级为 `15D`、等级 20；不超过 3 天升级为 `3D`、等级 30。
- 标题：`企业资料即将进入清理流程`
- 内容模板：`您的套餐已于 {套餐结束时间} 结束，相关车险业务资料预计自 {清理时间} 起进入清理流程，剩余 {剩余天数} 天。请在期限前重新开通套餐并备份所需资料。`
- 失效时间：资料清理日；超过清理日后不再生成或展示该提醒。

## 4. 同类提醒合并规则

企业门户表和客服监控表均以 `enterpriseId + reminderKey` 识别同一个业务事件。`reminderKey` 会包含订阅、套餐周期、续费时间、钱包欠费周期、暂停时间或资料清理时间，避免不同业务周期相互覆盖。

合并遵循以下规则：

1. 首次触发时新增一条提醒，`revision=1`、`triggerCount=1`。
2. 后续扫描只有在新阶段等级高于已有阶段等级时才更新原提醒，不新增第二条同类事件。
3. 相同阶段或更低阶段的重复计算被忽略，防止定时任务每天生成重复提醒或发生阶段倒退。
4. 阶段升级时更新标题、内容、业务快照、最后触发时间及失效时间，并增加版本号和触发次数。
5. 企业门户提醒升级后自动设为未读，清空原阅读时间和阅读人。
6. 客服监控提醒升级后自动恢复为待处理；此前的处理时间、处理人和处理备注保存到“最近一次处理快照”字段。
7. SaaS 即使本地提醒因相同阶段未更新，仍会调用一次监控系统合并接口，用于补偿此前可能发生的跨服务请求失败。

典型合并示例：套餐到期提醒在剩余 7 天时创建 `7D` 阶段；剩余 6～2 天期间不会重复更新；剩余 1 天时将原提醒升级为 `1D`，而不是再新增一条提醒。

## 5. 门户展示规则

- 查询范围：只返回当前企业最近一个自然月内触发且尚未超过 `expiresAt` 的提醒。
- 排序优先级：`CRITICAL > WARNING > NOTICE`。
- 同一严重程度：按最后触发时间倒序，最近提醒在最上方。
- 时间仍相同时：按提醒 ID 倒序，保证顺序稳定。
- 前端展示的提醒时间来自 `lastTriggeredAt`，接口字段为 `occurredAt`。
- 查询接口：`GET /portal/reminders/recent`。

## 6. 企业门户与客服监控的差异

| 项目 | 企业门户提醒 | 客服监控提醒 |
| --- | --- | --- |
| 使用对象 | 当前企业用户 | 平台客服人员 |
| 文案 | 面向企业，以“您的套餐/账户”表达 | 自动附加严重程度、企业名称和企业编码 |
| 阅读/处理状态 | 已读、未读 | 待处理、已处理 |
| 阶段升级 | 自动恢复未读 | 自动恢复待处理，并保存上次处理快照 |
| 合并标识 | `enterpriseId + reminderKey` | `enterpriseId + reminderKey` |
